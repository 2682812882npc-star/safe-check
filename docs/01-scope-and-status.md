这些版本说明原实验依据。换系统、加入域、成为域控或更换基线后，必须重新核对适用性；不能直接把旧表当作新环境合规结论。

## 历史阶段

1. **Windows检查和手工加固记录**：原笔记包含14组人工检查及分批整改。自动化源码包还包含一套273项映射和离线测试。
2. **Windows自动化检查结果的历史复核**：原笔记记录59符合、42不符合、11不适用、1未检查、160待确认。这是已保存材料的历史统计，本仓库未包含原始结果归档，未重新采集或重新计算，不能当作当前主机状态。
3. **Ubuntu初步检查**：九领域笔记完成后仍有适用性和证据待收尾；其中“未加固”的描述对应初查阶段。
4. **Ubuntu后续练习**：随后进行了SSH权限、sudo伪终端、SSH Banner、密码最长有效期、journald容量五项代表练习；这更新了所选项目，不等于全部差异均已修复。
5. **2026-10-26整理**：制作可上传目录，整理案例、去除实际身份及原始采集附件，执行离线验证。

## 结论能写到什么程度

| 对象 | 能支持的描述 | 保留事项 |
| --- | --- | --- |
| Windows自动化包 | 有源码、逐项映射和模拟判定测试 | 模拟结果不证明目标VM上原生API均可用 |
| Windows日志/审核/SMB案例 | 原笔记记载相应配置复查通过 | 事件、共享会话等功能验证仍按案例列出 |
| WinRM | 原笔记记载管理来源到TCP 5985连通 | 实际认证及非授权来源拦截未验证 |
| ASR | 选定LSASS规则查询为阻止值1 | 实际阻断和业务兼容性未验证 |
| Ubuntu SSH权限 | 所选两个文件0600、root:root复查通过 | 不扩大为所有Include文件或全部SSH安全项 |
| sudo | 配置、语法、指定账号适用规则已核对 | 实际执行因认证失败未完成 |
| Banner | 首轮有提示展示记录及用户登录确认；之后有回退纠正 | 重新应用后仅收到用户确认，未补完整新证据链 |
| journald | 最新启动记录max 1.0G，与所设1G一致 | 3G保留为配置证据；未做耗尽磁盘测试 |

公开仓库用于展示方法、代码和有限证据的案例摘要。完整原始证据继续保存在本地原压缩包中。
